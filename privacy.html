Privacy

What kyōki stores when it runs in a Discord server. Written from the bot’s actual code, in plain English.

20 November 2026 · America/Los_Angeles

Who this is for

This page is for people who add kyōki to a server, and for members of those servers. It describes the Discord bot and this website. If something is not listed here, it is because the code does not store it.

Guild settings

For each server the bot is in, kyōki keeps a settings record. That record can include:

  • The server’s command prefix (the default is a comma).
  • Welcome and goodbye: the channel, and the message text or embed JSON.
  • The log channel, if one is set.
  • Automod: which filters are on, what they do, blocked words, allowed domains, roles and channels the filters skip, a filter log channel, and the timeout length.
  • Antinuke and antiraid settings, including user or bot IDs on the antinuke whitelist.
  • Ticket settings: the category, support role, transcript log channel, a ticket counter, and — for tickets that are still open — the channel, owner, claimer, and when it was opened.
  • VoiceMaster: the category, interface, Join-to-Create channel, and records of temporary channels.
  • Starboard: the channel, threshold, emoji, and a map of original messages to starboard posts.
  • Sticky messages: the text or embed JSON for each channel, how often to repost, and the last posted message ID.
  • Autoresponder triggers and responses.
  • Giveaways: prize, host, channel, end time, entrant user IDs, and winners. Ended giveaways are removed from the bot’s data after 30 days.
  • Reaction roles, and which button-role messages are set to unique mode.
  • The mute role; lockdown ignored and locked channels; hardbans; tempbans; role mutes; roles saved for restore; forced nicknames; and jail records.

Changes you make in the dashboard, once it is open, are applied to these same guild settings.

Warnings, cases, and notes

Warnings store who issued them, the reason, and when. Cases store the action, the user’s ID and name, the moderator’s ID, the reason (up to 500 characters), the time, and any extra fields for that action. Private staff notes store who wrote them, the text (up to 500 characters), and when. Server staff can view, change, or delete these with the case, warning, and notes commands.

Tickets and transcripts

While a ticket is open, the bot stores the facts listed above. When a ticket is closed, kyōki builds a .txt transcript of up to 5,000 messages in that channel — author name and ID, message content, embed text, and attachment URLs — and posts the file to the server’s ticket log channel, or to the main log channel if no ticket log is set. If neither channel is set, the transcript is not posted. The transcript is not kept in the bot’s data file after the ticket is closed. The open-ticket record is removed, and the ticket channel is deleted a few seconds later.

AFK and reminders

An AFK status stores your reason (up to 200 characters) and the time you set it. It is cleared when you send a message in that server (except the ,afk command itself). Mentions of you can show that reason until it is cleared.

Reminders store your user ID, the channel, the time, the text (up to 1,500 characters), and a link to the original message, until the reminder is sent or you delete it. You can have up to 25 reminders at once in a server.

Snipe cache

The last 20 deleted messages and the last 20 pre-edit messages in a channel are kept in the bot’s memory only — author, content, attachment URLs or a jump link, and the time. They are not written to the data file. They disappear when the bot restarts, or when someone with Manage Messages runs ,clearsnipe in that channel.

Logging in your server

If a server sets a log channel, the bot posts events there. That can include deleted and edited message content, bans and unbans, and other events the bot already logs. Those posts live in the Discord channel the server chose, not in the bot’s data file.

Dashboard sessions

If you log in to the dashboard, a cookie holds only a signed session ID. Your Discord account details and access token are kept in the dashboard server’s memory. Restarting the dashboard logs everyone out. The dashboard reads guild settings and queues changes for the bot to apply; it does not write the data file itself.

The public status file

The status page is fed by a file the bot updates about once a minute. It stores whether the bot is online, aggregate server and member counts, latency, shard info, and SHA-256 hashes of guild IDs — not the raw guild IDs.

This website

The kyōki website is a static site. It does not set a login cookie in your browser unless you use the dashboard.
